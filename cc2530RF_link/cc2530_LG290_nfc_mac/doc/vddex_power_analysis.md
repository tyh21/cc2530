# VDDEX(P2.3) 供电问题分析 —— 实测 P2.3 ≈ 0.6V

> ★★★ 2026-10-05 更新 (v27h 固件隔离实验): **结论已定性 —— P2.3 引脚被外部钳死。**
> 决定性对照: `[CMP] round0  P2.0_driveHi=1   P2.3_driveHi=0`
> 同一段代码、同一驱动方法, P2.0 驱高读回 1、P2.3 驱高读回 0
> ⇒ 测量方法/固件无误, **P2.3 这一路硬件被钳在低**。

> ★★★★ 2026-10-05 追加 (万用表测 P2.3 对 GND): **不是纯电阻短路 —— 有 PN 结特性**
> 实测 "正向大、反向 400Ω" = 二极管单方向导通特征。
> ⇒ **① 推翻"P2.3 对地短死"的旧判读；② 能测到结 ⇒ P2.3 与芯片 VDDEX 走线是通的。**
> 详见 §0b。这条数据把问题从"走线断/短"改写为"**二极管把节点钳在 0.6V**"。

> 现象: 213 板与 290 板**都一样**，固件把 P2.3 推挽驱高时，用万用表量 P2.3 只有 **≈0.6V**，到不了 3.2V。
> 固件侧同时回读 P2.3 = 0（`bit3=0`），与 0.6V 吻合（0.6V < CC2530 VIH≈2.3V）。

## 0b. ★★★★ 决定性新增数据：P2.3 对 GND 的万用表测量 (2026-10-05)

**用户实测（万用表欧姆/二极管档，断电，P2.3 对 GND）：**

| 表笔方向 | 读数 |
|---|---|
| 正向 | **大**（高阻/OL） |
| 反向 | **约 400 Ω** |

**判读：这是标准的 PN 结单方向导通特征，不是电阻性短路。**

### 万用表极性约定（对解读至关重要）
> 机械/数字万用表欧姆档：**红表笔 = 表内电池正极（+）**，**黑表笔 = 表内电池负极（−）**。
> 电流从红表笔流出 → 经被测物 → 流回黑表笔。

- **"反向 400 Ω"那一侧**（电流能通、只 400 Ω）即 **二极管正向偏置** 方向。
- 若该方向是 **GND → P2.3**（红笔接 GND、黑笔接 P2.3）：二极管 **阳极在 VSS、阴极在 VDDEX**。
- 若该方向是 **P2.3 → GND**（红笔接 P2.3、黑笔接 GND）：二极管 **阳极在 VDDEX、阴极在 VSS**。

### 两个直接结论（不依赖极性歧义）

**结论 1：P2.3 **不是** 纯电阻对地短路。**
旧判读（`h_P23holdMs=0` ⇒ "近似裸低阻到地"）**作废**：
- 400 Ω 且**正反不对称** ⇒ 是半导体结，不是导线/焊锡短路；
- `hold=0ms` 与"挂电容"并不矛盾 —— 若漏电支路就是这 400 Ω，
  则 **400 Ω × 2.2 µF ≈ 0.88 ms**，远小于 1 ms 的测量步进（`NFC_DelayMs(1)`），
  所以放开后**必然读不到高**，与电容存在**完全自洽**。
  ⇒ **`hold=0` 不能再作为"无电容/裸短路"的证据。**

**结论 2：能测到 PN 结 ⇒ P2.3 与 MN63Y1213 的 VDDEX(pin2) 走线是连通的。**
- 若 P2.3 与芯片之间走线断开（旧"可能 1"），则 P2.3 侧量不到芯片的 ESD 结，
  只会量到 PCB 走线的开路/对地寄生 —— **不会有 400 Ω 的规整二极管读数**。
- ⇒ 旧的"走线中间断"假设**基本排除**；两侧是**同一个节点**。

### 由此得到的物理模型（修正 §3 的模型 A）

```
                400Ω (二极管, 单向)  ← 实测
CC2530 P2.3 ──┬──────────────────────► VSS
   (pin33)    │
              ├── MN63Y1213 VDDEX (pin2)   ← 走线连通(结论2)
              │
              └──(若有 R0)── 3.3V 轨
```
- **MCU 推挽驱高时**：电流经这个二极管流走 ⇒ 节点被**钳在二极管正向压降 ≈ 0.6 V**。
  **这正好解释万用表读到的 0.6 V**（0.6 V = 硅 PN 结正向压降，与实测一字不差）。
- 三个独立证据指向同一结论：
  1. 电压 0.6 V（= PN 结正向压降）；
  2. 对 GND 有单向二极管（400 Ω 正偏 / 反向高阻）；
  3. 推挽 20 mA 也拉不动（被结钳位，非被大电容拖住）。

### 还剩一个必须由用户确认的歧义：这个 400 Ω 是"正常寄生结"还是"击穿漏电"

- **若为正常 VDDEX 对 VSS 的寄生/ESD 二极管**（阳极 VSS、阴极 VDDEX）：
  它在 VDDEX 正常加正压时**反偏**，**不该在 3.3 V 下导通**。
  现在 P2.3 驱高就 0.6 V ⇒ 说明该结**正偏导通** ⇒ 该二极管的**导电方向是 P2.3 → VDDEX 内部 → VSS**，
  或 **该结已击穿/被结构性正偏**（例如 VDDEX 与 VSS 在版图/键合上被接反、或 ESD 单元损坏）。
- ⇒ **需要补一条测量来定死方向**（见 §4 测 1b）。

## 2. 官方文档依据

**MN63Y1213 应用笔记 (APN_NFC_TAG_EN.pdf v1.7, Nuvoton/NTCJ)**

- **P14 Host control block**：驱动 VDDEX 的 GPIO **只需 ≥500 µA** 输出能力。
  → 官方就允许 **host GPIO 直驱 VDDEX**；正常电流几百 µA 量级。
  → **CC2530 GPIO 能出 20mA，供 500µA 绰绰有余** → 0.6V 必是异常。
- **P15 Peripheral Components**：
  | 元件 | 值 | 作用 |
  |---|---|---|
  | R0 | ①0Ω(1.7~2.5V) ②200Ω(2.5~3.6V) | VDDEX 到 3.3V 的上拉/稳定电阻 |
  | C2 | ①0.1~2.2µF ②2.2µF | VDDEX–VSS 去耦 |
  | C1 | 2.2µF | VDDA–VSS 去耦 |
  | R2/R3 | 3.3kΩ | SDA/SCL 上拉到 VDDEX |
- **P15 参考电路**：VDDEX 网络 = GPIO + R1(200Ω→3.3V) + C2(2.2µF→VSS) + 芯片 pin2。

**MN63Y1213 数据手册**
- VDDEX = "contact power supply"，工作范围 **1.7~3.6V**；芯片内置 **5V clamp circuit**。
- P19：VDDEX 必须接去耦电容到 VSS；SDA/SCL/NIRQ 上拉到 VDDEX。

## 3. 0.6V 的物理模型（2026-10-05 修正）

### 模型 A′（★ 现行最符合全部实测）：P2.3 上有单向 PN 结，把节点钳在 0.6V
```
CC2530 P2.3 ──┬──[PN 结, 实测 400Ω 单向]──► VSS
              │
              └── MN63Y1213 VDDEX(pin2)   ← 走线连通(§0b 结论 2)
```
支持证据（三条独立、互相印证）：
1. **电压 0.6 V** —— 正好是硅 PN 结正向压降；
2. **对 GND 单向 400 Ω**（正反不对称）—— 半导体结特征（§0b）；
3. **推挽 20 mA 拉不动** —— 被结钳位，而非被大电容（电容会被 20 mA 充上去）。
- 待定：这个结是"芯片 VDDEX 内部正常寄生二极管被异常正偏/击穿"，
  还是"板级某个保护二极管误装/损坏"。由 **§4 测 1b** 定死方向后即可分辨。

### 模型 A（旧，仍可能）：芯片内部二极管钳位
```
CC2530 P2.3 ──┬── MN63Y1213 VDDEX(pin2) ──[内部钳位]──► VSS   (0.6V 正向压降)
              └─(若有 R0 200Ω)→ 3.3V
```
- 与 A′ 的区别只在"结在哪一侧、方向如何"；物理效果相同（钳 0.6V）。

### 模型 B：3.3V 轨没接上 + GPIO 供不动（★ 已弱化，但仍需测 2 排除）
- 板上 VDDEX 的 R0(→3.3V) 通路断/未贴/3.3V 轨没电，只剩 GPIO 在供。
- **判据**：量 3.3V 轨/电池正常，但 VDDEX 节点仍 0.6V；外部 3.3V 经 1kΩ 试供能抬起。
- ⚠️ 注意：若真有 400 Ω 对地结，则"外部 3.3V 经 1 kΩ 送电"也**抬不起来**
  （1 kΩ 分压后 ≈ 0.94 V）。要试就用 **≤100 Ω 或直接短接**，并测流过的电流。

## 4. 给用户的最小实测清单（按信息量排序）

1. **断电量 P2.3 ↔ VSS 电阻，正反各一次**
   - 单向 ~0.5-0.7V 压降 + 反向 OL → **模型 A（芯片钳位）**
   - 两向同低阻 → 电阻性短路
2. **上电、固件驱高窗口内量各点电压**
   - a) CC2530 P2.3(pin33)   b) MN63Y1213 VDDEX(pin2)
   - c) 板上 3.3V 轨/电池正   d) VR0 两端
   - 若 b ≫ a → 中间串阻压降；若 c 有 3.0V 但 b 只有 0.6V → R0 通路没接上
3. **量电池/3.3V 轨对 GND** —— 确认主板供电正常
4. **量 MN63Y1213 VDDA(pin8) 对 VSS** —— 应有 2.2µF，悬空/短路即异常
5. **外部 3.3V 经 1kΩ 直接给 VDDEX(pin2) 送电**，看能否抬到 2.5V+

## 4b. 实操夹具（万用表怎么摆表笔）

设 `VSS` = 电池负极 / 板上 GND 大面积铺铜（任选一个稳定测试点，如屏蔽罩或电池焊盘负极）。

**测 1（断电，最关键）—— 区分 A/B：**
```
万用表 → 二极管档（带蜂鸣，读数即 mV 压降）
红表笔接 P2.3（pin33 或板上 VDDEX 焊盘），黑表笔接 GND
→ 记录读数。若非 OL：读数为 ~500-700mV 且能蜂鸣 → 内部二极管正向导通 → 模型 A
交换表笔（红→GND，黑→P2.3）再测
→ 若反向 OL / 读数远大于正向 → 二极管特性确认 → 模型 A
→ 若正向/反向都是几十~几百 Ω 且接近 → 纯电阻性下拉/短路
```
> 没有二极管档就用欧姆档：二极管特性表现为正/反向电阻明显不对称。

**测 1b（★★★ 2026-10-05 新增，最关键的一条）—— 定死 400Ω 二极管的方向：**

```
用万用表【二极管档】（不是欧姆档）断电测：
  (a) 红笔 → P2.3(pin33 或 VDDEX 焊盘)，黑笔 → GND
      → 读 mV。若显示 "OL" 或 >2V    = 此方向不通（反偏）
      → 若显示 400~700mV 且蜂鸣       = 此方向导通（正偏）
  (b) 交换表笔：红笔 → GND，黑笔 → P2.3
      → 记录读数。

结论矩阵：
  (a)=OL 且 (b)=500~700mV  → 二极管【阳极=VSS，阴极=VDDEX】
       这是 VDDEX 脚**正常的**寄生/ESD 二极管方向。
       正常时它在 VDDEX 加正压时应【反偏不导通】。
       现在却把节点钳在 0.6V ⇒ **该结异常正偏** ⇒ 芯片 VDDEX 内部已损坏
       （ESD 单元击穿 / 结被结构性短接）→ 需换芯片。
       ★ 但注意：若真如此，芯片 VDDEX 引脚内部对 VSS 呈现 ~400Ω，
         那 3.3V 经 400Ω 也只能提供 ~8mA，芯片可能勉强能工作 —— 值得一试外部送电(测5)。

  (a)=500~700mV 且 (b)=OL  → 二极管【阳极=P2.3，阴极=VSS】
      这说明 P2.3 节点上对地挂了一个"阳极朝 P2.3"的二极管 —— 
      正是它把 P2.3 驱高的电压钳在 0.6V。可能是板级保护元件或误装。

  两向读数接近（都是几百 Ω）→ 电阻性通路（不是结），回到"短路"模型。
```

> 表笔极性口诀：**欧姆/二极管档，红笔 = 表内电池 + ，黑笔 = − 。**
> 二极管正向 = 电流 红→黑；所以"**哪个方向读数小，二极管的阳极就在红笔那一侧**"。

**测 2（上电，在 3s 驱高窗口内）—— 逐点电压（窗口已从 30s 缩到 3s，见 main.c）：**
```
固件跑起来后立刻依次量：
  a) CC2530 pin33 (P2.3)            → 预期 0.6V
  b) MN63Y1213 pin2 (VDDEX)         → 与 a 比较
  c) 板上 3.3V 轨 / 电池正极        → 预期 ≥3.0V
  d) 若是 R0 两端可及，量 R0 两端     → 压差 = 电流×阻值
判断：
  b ≈ a（都 0.6V）且 c 有 3.0V     → R0→3.3V 通路存在但被结拉低 → 模型 A
  b ≈ a 且 c 也只有 0.6V           → 整条 3.3V 轨没电 → 先查主板供电
  b ≫ a                            → 中间有串阻/走线压降 → 查 P2.3→pin2 之间元件
```

**测 3（断电）—— 电源轨是否还在：**
```
量电池两端电压 → 应 ≥3.0V（CR2032 满电 3.0~3.2V，<2.7V 该换）
量 3.3V 轨对 GND → 应 ≥3.0V
```

**测 4（上电）—— 让 VDDEX 悬空后再量：**
```
临时用一根飞线把 P2.3 从 VDDEX 节点断开（割线/挑脚），或固件里先不让 P2.3 驱高，
只让 3.3V 经板上 R0 供。
  → 若断开后 a 点能升到 3.0V 以上 → 是 VDDEX 侧吸流（模型 A）实锤
  → 若断开后仍 0.6V           → 问题在 MCU 侧（P2.3 本体异常）
```

## 5. 若确认是模型 A′/A（结钳位）的可能处置

- 手册明确说 **"also possible to supply a voltage to VDDEX directly from the power
  supply, not from the host's GPIO"** → 可改用**电源轨经 MOSFET/电阻开关供电**，
  而不是靠 GPIO 直驱（GPIO 只做"使能"控制 MOSFET）。
- ★ 但若 400 Ω 结确实存在，则**任何"低电流"供电都会先被这个结吃掉**：
  在 3.3 V 下它要吃掉 **3.3 / 400 ≈ 8 mA**，且把 VDDEX 钉在 0.6 V。
  ⇒ 这条路**软件层面无法解决**，必须硬件处理（换芯片/换板/割断该结）。
- 「用短路/低阻把 VDDEX 硬接到 3.3V」是本项目**唯一可能绕过**的办法：
  若 3.3 V 轨足够硬，能顶住 8 mA，VDDEX 就能上到 3.3 V —— 但这是在**给一个疑似损坏的
  结持续灌电流**，有发热/进一步损坏的风险，仅在确认芯片尚能工作的前提下短时试。
- 若芯片本身损坏（内部结击穿）→ **需换芯片/换板**。

## 7. ★★★★ RF 场供电实验 (2026-10-05, v30b/v30c/v30d) —— 决定性对照

**动机**: 用户提出"没准这个需要 RF 端打开" —— MN63Y1213 是**双接口**芯片,
RF 侧(线圈)有整流器, 手机 NFC 场可能经线圈把芯片供起来。用户手机 NFC Tools
**能识别到这张标签**(只是"写错误"), 证明芯片 RF 侧 + 芯体是活的。

**做法**: `V30_RFWATCH` 条件编译出专用 main(), SDA/SCL/P2.3 **全部三态放开**
(不驱动、关内拉), 只读三个"芯片自己说话"的信号:
`nirq`(P1.0) / `P23`(VDDEX 节点电平) / `line`(SDA,SCL 电平)。

### 实测数据 (手机贴上、停留 13~25s)

| 版本 | 触发方式 | 结果 |
|---|---|---|
| v30b | 纯被动观测 | `P23` 0→1、`line` 0x00→0x03, 但无命令故 NIRQ 不动 |
| v30c | P23 **上升沿**抢读 | `s5=00000 k=3 STUCK` / `rm=1 NOACK`（读早了, 那时 line 还是 0x00） |
| v30d | **等 line=0x03 后**抢读 | `s5=00000 k=3 STUCK` / `rm=1 NOACK` |

v30d 完整时间线 (245 样本 × 100ms = **24.5s**):
```
全程: nirq=1  P23=1  line=0x03   (nHi=245, nLo=0)
n=0 触发抢读:  s5=00000  k=3 (STUCK)   rm=1 (NOACK)
```

### 结论

1. ✅ **RF 场确实给 VDDEX 节点供了电** —— `P23` 稳定为高 24.5s。
   用户"需要 RF 端打开"的**假设方向正确**。
2. ✅ **外部上拉起作用了**(`line=0x03`) —— 两线被静态拉到高, 说明芯片侧有电、
   引脚不再把线钉死。
3. ❌ **但仍读不了**: 主机拉 SCL 时 SDA 被**动态钉低**(`s5=00000 k=3`),
   块寻址命令**零 ACK**(`rm=1`)。

### 为什么"线能拉高"却"读不了" —— 自洽解释

- `line=0x03` 只需**上拉电阻(几千欧)+ 一点点电压**即可实现, 甚至芯片 I2C 引脚
  处于高阻"未唤醒"时线也是高的;
- "读"要求芯片**在 SCL 时钟节拍下动态拉低 SDA 应答**, 需要 I2C 状态机真被唤醒;
- `s5=00000` = SCL 一跳 SDA 就被钉死 ⇒ **总线被低阻通路钳住**, 不是芯片在应答;
- **最可能**: RF 场给 VDDEX 抬起的电压与 MCU 3.3V 域**打架** —— P2.3 上那个
  **400Ω 单向 PN 结**依然是那条低阻通路, SCL 一开关就表现为 SDA 被钉低。

**⇒ 软件侧实验至此穷尽**(上电时序/延时扫描/双地址/块寻址/寄生供电/RF 场供电
全部试过)。瓶颈**确定性地落在硬件**: P2.3/VDDEX 网络的 400Ω PN 结使外部供电
进不来、MCU 驱动又被钳住; RF 场虽能抬节点电位, **不足以绕过钳位让 I2C 状态机跑起来**。

## 6. 2026-10-05 结论一句话

**P2.3(VDDEX) 上存在一个单向 PN 结（实测 400 Ω 正偏），把该节点钳在 0.6 V —— 这不是
"对地短死"，而是"被二极管钉死"。走线是通的（能测到结），所以问题在芯片 VDDEX 引脚
（或板上该网络的保护结），不在 MCU、不在固件、不在走线。**
RF 场实验(v30b/c/d)进一步证明: **芯片 RF 侧是好的、RF 场能给节点供电**,
但那条 400Ω 结依然让 I2C 收发无法进行。
下一步只需**一条**万用表测量（§4 测 1b，定死二极管方向）即可收口。
- 复核板载 R0 实际值：若是 200Ω 且芯片吸流大 → 可考虑改小串阻（但要看手册档位）。
- ★ 顺带: 手机贴卡时量 VDDEX(pin2) 对 GND 电压 —— 若仍 ~0.6V 不动,
  证明 RF 场供电被结吃掉; 若能上到 1.7V+, 则值得试"读前先给 VDDEX 充电"的时序。
